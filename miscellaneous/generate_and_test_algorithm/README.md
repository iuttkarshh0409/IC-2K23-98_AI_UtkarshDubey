# Generate and Test Algorithm

## Practice Problems

A systematic collection of the Generate-and-Test problems practiced during the session, arranged from basic to more challenging.

---

## Problem 1: Find a Number Whose Square Is 144

### Problem Statement

Find a number between **1 and 20** whose square is **144**.

### Task

Using the **Generate-and-Test algorithm**, identify:

1. The candidate generation strategy.
2. The test condition.
3. The candidates generated, in order.
4. The point at which the algorithm stops.

### Core Test

```text
candidate × candidate == 144
```

### Learning Focus

* Basic Generate-and-Test structure.
* Systematic versus constrained candidate generation.
* Using mathematical properties to reduce the search space.

## Problem 2: Find Two Numbers Whose Sum Is 11

### Problem Statement

Find **two numbers between 1 and 10** whose sum is **11**.

### Task

Using the **Generate-and-Test algorithm**, identify:

1. The candidate generation strategy.
2. The candidate pairs generated.
3. The test condition.
4. The point at which the algorithm stops after finding a valid pair.

### Core Test

```text
candidate1 + candidate2 == 11
```

### Learning Focus

* Generating candidate pairs.
* Testing candidate combinations.
* Understanding when the search should terminate.
* Distinguishing between finding **one valid solution** and finding **all valid solutions**.
* Understanding the difference between a guaranteed search strategy and a heuristic optimization.

## Problem 3: Find a Number Whose Square Is 625

### Problem Statement

Find a number between **1 and 50** whose square is **625**.

### Task

Using the **Generate-and-Test algorithm**, identify:

1. A basic candidate generation strategy.
2. An optimized candidate generation strategy.
3. The test condition.
4. The candidates generated by the optimized strategy.
5. The point at which the algorithm stops.

### Core Test

```text
candidate × candidate == 625
```

### Example of a Constrained Generator

A candidate whose square ends in `25` must end in `5`.

Therefore, within the range 1–50, promising candidates include:

```text
5, 15, 25, 35, 45
```

The algorithm can test them sequentially until a valid solution is found.

### Learning Focus

* Constraint-based candidate generation.
* Reducing the search space before testing.
* Distinguishing valid optimization from unnecessary complexity.
* Understanding that the generator can use problem-specific knowledge.

## Problem 4: Find a Number Whose Cube Is 729

### Problem Statement

Find a number between **1 and 100** whose cube is **729**.

### Task

Develop two Generate-and-Test approaches:

#### Approach 1: Optimized Generation

Use a mathematical property of the units digit to reduce the candidate search space.

Identify:

1. The mathematical constraint.
2. The candidate generation strategy.
3. The test condition.
4. The candidates generated.
5. The point at which the algorithm stops.

### Useful Observation

If a number ends in `9`, its cube also ends in `9`.

Therefore, candidate numbers ending in `9` can be generated:

```text
9, 19, 29, 39, 49, 59, 69, 79, 89, 99
```

The first candidate already satisfies the condition:

```text
9³ = 729
```

#### Approach 2: Traditional Generate-and-Test

Generate candidates sequentially:

```text
1, 2, 3, 4, ...
```

Test each candidate by calculating its cube until the target is found.

### Core Test

```text
candidate × candidate × candidate == 729
```

### Learning Focus

* Traditional Generate-and-Test.
* Optimized candidate generation.
* Mathematical constraints for reducing search space.
* Comparing brute-force and optimized generation.
* Understanding the importance of proving that an optimization does not eliminate valid solutions.

# Overall Learning Progression

The problems progressively introduce different levels of candidate generation:

```text
Problem 1
Basic search + simple constraint
        ↓
Problem 2
Candidate pairs + search strategy
        ↓
Problem 3
Constraint-based search-space reduction
        ↓
Problem 4
Mathematically justified optimization
        ↓
Generate-and-Test
```

## Key Principle

The general Generate-and-Test pattern used throughout these problems is:

```text
Generate a candidate
        ↓
Test the candidate
        ↓
Is it a valid solution?
   ↙             ↘
 YES             NO
  ↓               ↓
STOP        Generate next candidate
```

The quality of the algorithm depends heavily on how intelligently the **candidate generator** explores the search space while still guaranteeing that a valid solution has not been eliminated.
